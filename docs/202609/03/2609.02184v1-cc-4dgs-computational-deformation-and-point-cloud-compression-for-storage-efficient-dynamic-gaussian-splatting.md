## 摘要
动态四维（4D）高斯溅射已成为高质量视图合成的强大显式表示，然而现有方法由于严重依赖大型多分辨率哈希表和高维高斯属性，每个场景仍需要数十至数百兆字节的存储空间。本文提出了CC-4DGS，一种存储高效且可扩展的框架，重新思考了变形建模和规范属性存储。首先，我们引入了一种计算变形场（CDF），用确定性密集哈希编码和紧凑型神经解码器取代大型多分辨率可学习哈希表，能够即时合成变形特征，同时将每场景的变形存储减少至仅1-3 MB。其次，我们提出了一种规范点云属性（CCA）压缩流程，通过条件自编码、选择性量化和残差码本压缩高维球谐外观项和辅助高斯属性，实现3-5倍的点云缩减，且质量损失可忽略不计。这些组件共同形成了一个统一表示，在保持实时渲染性能的同时将总存储减少到20-30 MB。在N3DV和Technicolor Light Field数据集上的大量实验表明，CC-4DGS实现了与Swift4D等最先进方法相当的重建精度，同时提供了显著改善的存储效率和有利的运行时-内存权衡。

## Abstract
Dynamic four-dimensional (4D) Gaussian Splatting has emerged as a powerful explicit representation for high-quality view synthesis, yet existing methods still require tens to hundreds of megabytes per scene due to their heavy reliance on large multi-resolution hash tables and high-dimensional Gaussian attributes. This paper presents CC-4DGS, a storage-efficient and scalable framework that rethinks both deformation modeling and canonical attribute storage. First, we introduce a computational deformation field (CDF) that replaces large multi-resolution learnable hash tables with deterministic dense hash encoding and compact neural decoders, enabling on-the-fly synthesis of deformation features while reducing deformation storage to only 1--3 MB per scene. Second, we propose a compression of canonical point-cloud attributes (CCA) pipeline that compresses high-dimensional spherical harmonic appearance terms and auxiliary Gaussian attributes via conditional autoencoding, selective quantization, and residual codebooks, achieving 3--5$\times$ point-cloud reduction with negligible quality loss. Together, these components yield a unified representation that preserves real-time rendering performance while reducing total storage to 20--30 MB. Extensive experiments across the N3DV and Technicolor Light Field datasets demonstrate that CC-4DGS achieves reconstruction accuracy comparable to state-of-the-art methods such as Swift4D, while offering significantly improved storage efficiency and favorable runtime-memory trade-offs.

# CC-4DGS 论文详细总结

## 1. 核心问题与研究动机

动态4D高斯溅射（Dynamic 4D Gaussian Splatting）已成为高质量动态视图合成的重要显式表示方法，但其**存储开销巨大**：现有方法通常需要单个场景数十至数百MB的存储空间，主要源于两大部分：

- **变形场存储**：大量依赖多分辨率可学习哈希表（如Grid4D、Swift4D），可占据几十至几百MB。
- **规范高斯属性存储**：高维球谐（SH）系数和逐高斯辅助特征也是存储主体，其中SH-AC部分约占点云数据的70%。

这一存储瓶颈严重制约了模型在**流媒体传输、移动/边缘设备、云存储**等场景中的实际部署。现有压缩手段（如Scaffold-GS、MoDec-GS等）多基于参数共享、剪枝和熵正则化，但仍依赖大规模显式参数，无法从根本上解决存储问题。因此，论文提出应从**数据结构设计本身**出发，重新思考变形建模与属性存储两个环节，而非仅靠后处理压缩。

## 2. 方法论：CC-4DGS 框架

CC-4DGS采取双管齐下的存储优化策略，整体流程如下：

1. 使用COLMAP初始化规范高斯点集；
2. 将高斯分为**静态**与**动态**子集；
3. 动态子集通过CDF获得逐时间戳的变形；
4. 优化完成后通过CCA对规范点云属性进行压缩存储。

### 2.1 计算变形场（CDF）

**核心思想**：用“计算”替代“存储”，将大哈希表替换为轻量级神经解码器，运行时合成特征而非查表。

具体包含以下子模块：

- **多分辨率体素网格构建**：将规范空间坐标归一化后离散化为体素顶点坐标，建立4~5层分辨率层次（远少于以往常用16层）。
- **密集哈希编码（Dense Hash Encoding）**：借鉴DHE（Deep Hash Embedding）思想，每个顶点经过k=128个平行通用哈希函数映射，形成高维签名向量，降低冲突率。
- **哈希特征解码器（Hash Feature Decoder）**：各分辨率层配置独立的小型MLP解码器（由Linear、Mish、LayerNorm构成），将哈希签名在线映射为连续特征。
- **三线性插值**：将体素八个顶点的解码特征插值为高斯中心处的空间特征。
- **时间编码与融合**：采用频域位置编码加TimeMLP获得时间特征，再通过**FiLM（特征级线性调制）**机制对空间特征进行通道级调制，融合得到时空特征。
- **变形估计网络**：采用Trunk-Branch结构，由共享主干提取全局上下文，再分叉到5个预测头，分别回归位置Δμ、尺度Δs、旋转Δr、不透明度Δo和SH系数Δc的偏移量。

为缓解CDF带来的计算开销，论文额外提出两项加速机制：

- **顶点复用（Vertex Reuse）**：将所有Gaussian所需的体素顶点去重后统一解码，再按索引查回各自特征，避免重复计算。
- **时空特征缓存（Spatial-Temporal Feature Caching）**：由于规范空间特征不随时间变化，仅在第一帧计算并缓存空间特征fvoxel，后续帧只计算时间特征与融合/变形部分，大幅提升渲染速度。

### 2.2 规范点云属性压缩（CCA）

**核心思想**：不同属性对信息损失的敏感度不同，按属性类型差异化处理。

- **保留全精度**：位置μ和SH-DC，保证几何稳定；
- **标量属性量化**：旋转r、尺度s、不透明度o用12位线性量化；动态指示符d因长尾分布采用**μ-law压扩**后再量化；
- **SH-AC外观压缩**：以SH-AC为主并结合几何上下文属性y=(μ, s, o, r, d)构成输入，经**条件自编码器**压缩为低维潜变量并量化；对重建残差进一步用256项**K-means残差码本**编码；
- **无损后处理**：所有量化结果经Zstandard无损压缩器打包。

### 2.3 损失函数

总损失包括L1重建损失、SSIM损失和对少数闪烁场景启用的光滑性正则项（对输入坐标做微小扰动，惩罚变形输出差异），光滑性权重随训练线性增。

## 6. 主要结论与发现

- 通过CDF（1.9MB变形存储）替换Swift4D/Grid4D中~68MB~221MB的哈希表，可显著降低形变模型存储；
- 应用CCA后点云从84.4MB降至27.7MB（约3×），总模型量降至约30MB，质量几乎无损失；
- 在统一的单步骤初始化协议下，CC-4DGS在N3DV上PSNR 32.06dB/SSIM 0.943，略高于Swift4D（32.06dB/0.944不显著差，低存储更优），在Technicolor上优于E-D3DGS约0.5dB；
- 渲染速度约113 FPS（N3DV），运用顶点复用+特征缓存后几近实时，在Techicolor上约64 FPS；
- 特征缓存可将稳态网格路径降至~0.8ms（优于Swift4D的1.8ms表查找），端到端FPS差距主要源于Swift4D使用更优的tiny-cuda-nn库；
- 稠密多哈希编码能显著抑制由哈希冲突引发的运动模糊/重影，提高PSNR约2dB；
- FiLM平均优于直接拼接（+1.01dB），但存在场景差异；
- 频域时间编码+3层TimeMLP为该设定下的最优组合；
- 序列超过300帧时，CC-4DGS的退化速度（−0.50dB @1200帧）比Swift4D（−1.25dB）更慢，初步显示较好的长序列鲁棒性；
- 在率失真平面上，CC-4DGS的所有配置均落在Swift4D更加紧凑的存储范围内。

## 7. 方法或实验设计的优点

- **从根本数据结构优化存储**：不依赖事后熵编码，而是直接用确定性哈希+神经解码器消除可学习哈希表，设计原则新颖、逻辑清晰；
- 引用DHE多哈希思想来消减哈希冲突，同时保留4~5层浅层级体素，避免过深层级造成的存储膨胀；
- **时空特征缓存**巧妙利用了规范空间不变性，将“计算换来存储省”对渲染流畅性的冲击降到最低；
- **顶点复用**有效削减多Gaussian共享顶点带来的冗余解码，思路简单而实用；
- CCA按属性敏感度分流压缩，重点压缩SH-AC并在压缩过程中附带几何上下文的信息注入，客观上提升了编码效率；
- 在多个部分均强调“资源均衡”，率-失真扫描、长序列压力测试、逐场景的消融分析等实验设计完整且有说服力；
- 明确展示“以训练时间换存储”的折中策略，并诚实定位PyTorch实现所造成的计算开销。

## 8. 不足与局限

- **训练成本较高**：约为1小时/场景，比Swift4D的25分钟长不少；这是换取存储节约所付出的代价，但在轻量级设备场景中可能不被接受。作者解释为主要是PyTorch算子非融合所致，未来可在代码层优化。
- **公平对比范围受限于统一协议**：与近期面向压缩/流式的4DGS方法（如Light4GS、GIFStream、MEGA、4DGC）仅在背景表格中横向引用了对方报告值，且分辨率、GPU或任务（流式/逐GoP）设定不一致，并未在同一基准下重跑。无法得出整体优势结论，仅给出操作点差异；在Technicolor上也只与E-D3DGS直接对齐。
- **长序列压力测试是单场景实验**：作者自述“单场景压力测试不能证明普遍的长序列可扩展性”，这限制了结论外推能力。
- **CDF可扩展性受限**：在1200帧时仍有约0.5dB的下降，这属于canonical+形变范式内的共通问题。论文也没有将CC-4DGS与4DGC/4DGV等GoP式切分方法在同协议上比较。
- **FiLM并非对每个场景稳定增益**：在cut_roasted_beef和flame_salmon上反而略降，存在场景相关波动。
- **依赖于COLMAP初始化的动态3DGS范式**：对单目或无重投影先验的输入并不适配，应用范围有一定限定。
- **没有进行与静态3DGS压缩方法（CompGS、EAGLES）的整合比较**：作者虽指出这些方法不作用于形变域，但也未实验验证CDF与这类属性压缩的相互兼容性。
- **技术产物尚依赖较多人工调节参数**：如层级数、码本大小、量化位宽、动态阈值ζ、FiLM开关等，不同场景可能需要重新调整，论文并未提供自动适配策略。
